# AGENTS.md

Personal portfolio site (single-page Next.js App Router project). No tests, no CI, no env vars, no data layer — all content is hardcoded JSX.

## Commands

- `npm run dev` — dev server (Turbopack)
- `npm run lint` — ESLint flat config, run with no args
- `npx tsc --noEmit` — typecheck (there is no `typecheck` script; tsconfig is already `noEmit`)
- `npm run build` — strongest single check (types + routes + Tailwind)

There is no test framework. Verify changes with lint + `tsc --noEmit`, and `npm run build` before calling work done.

## Toolchain quirks (verified in `next.config.ts` / `package.json`)

- **Next 16 + React 19 + Tailwind v4.** Consult `node_modules/next/dist/docs/01-app/` before using any Next API from memory (see block above).
- **React Compiler is enabled** (`reactCompiler: true` + `babel-plugin-react-compiler`). Do **not** add `useMemo`, `useCallback`, or `React.memo` — memoization is automatic and manual memoization is discouraged.
- **Tailwind v4 has no `tailwind.config.*`.** It is wired as a Turbopack loader rule in `next.config.ts`; theme tokens go in `src/app/globals.css` via `@theme`.
- `cacheComponents: true` and `partialPrefetching: true` are on — default caching/fetch semantics differ from older Next. Check the docs before assuming cached-by-default behavior.
- `LayoutProps<"/">` in `src/app/layout.tsx` is a **global type generated by Next** into `.next/types`. Keep it; don't replace with an inline props type.

## Structure & conventions

- `src/app/` — `layout.tsx`, `page.tsx`, `globals.css`, and `projects/[slug]/page.tsx` (no custom `not-found.tsx`; Next's default 404 applies). `page.tsx` composes sections in order: `Hero`, `About`, `Skills`, `Education`, `Experience`, `Projects`, `Contact`, then `Footer` (outside `<main>`). `Header` is rendered by `layout.tsx`, not `page.tsx`.
- `metadata` in `layout.tsx` is still the create-next-app boilerplate (`"Create Next App"`) — update it if you touch page metadata; don't assume it reflects the site.
- `src/components/portfolio/` — one section per file, zero props, static content inline. Every component has both a named export (`export function Hero()`) and a default export; imports use the named one. Follow this pattern for new sections.
- Only `header.tsx` and `hero.tsx` are client components (`"use client"`; header uses `useState`/`useEffect`, hero uses `typewriter-effect`). Everything else is a server component — keep it that way unless interactivity is needed.
- Project data lives in `src/components/portfolio/projects.tsx` (typed `Project` data + `projects` array + `getProjectBySlug()` + `ProjectPreview` + `featureIcons`); `src/app/projects/[slug]/page.tsx` imports from it — never duplicate project data. Three projects: `wanderlust`, `bangla-bazar-dhor`, `jubail24-news-bangla` (tech/feature lists were verified against each repo/live site — keep them accurate). The detail page is a server component using async `params`, `generateStaticParams`, `generateMetadata`, and `notFound()` for bad slugs.
- `dynamicParams` **cannot** be exported from pages here — `cacheComponents: true` disables it. Unknown slugs go through `notFound()`, which under Cache Components streams the 404 UI inside a 200 PPR shell on first hit (later hits return a real 404) — this is platform behavior, not a bug.
- Import via the `@/` alias (`@/*` → `./src/*`).
- Components are server components by default; add `"use client"` only when introducing interactivity.
- Dark slate theme (`bg-slate-950`) with blue accents, styled with inline Tailwind utilities. The `:root` color vars and `body` rule in `globals.css` are leftover create-next-app boilerplate — the visible body colors come from `className` on `<body>`.
- `hero.tsx` uses a plain `<img src="/banner.jfif">` (file lives in `public/`), which is the source of the repo's only lint warning (`no-img-element`). The "Get CV" button links to `/cv.pdf` with `download`, but **`public/cv.pdf` does not exist yet** — the link 404s until the file is added.
